## Goal

The Inspection Engine is "the operational heart of the platform" (Doc 10). An inspection is **not a form: it is the execution of a template** (Doc 10 §2): Template → Inspection → Observation → Finding → Corrective Action → Closure. This sprint builds that chain once, so every inspection type (daily safety, scaffold, excavation, fire, camp …) is a template a company configures, never code (Doc 10 §3, §20):

- **templates** with sections, items, allowed results, required evidence and scoring, **version-controlled**: an inspection keeps the version it started on, whatever happens to the template later (Doc 10 §4, §18);
- **inspections** planned for an inspector or started on the spot, captured on a phone **with or without a connection, including photos**, and synced through the Sprint 9 layer (D-11, D-20);
- the D-12 workflow **Draft → In Progress → Submitted → Approved → Closed**, every change logged (Doc 10 §5);
- a **review** by someone other than the inspector, who can return the inspection or approve it;
- **findings** generated from failed items and turned into **corrective actions** through `ActionEngine`; closing the last action closes the inspection (Doc 10 §11, §12).

## Definition of Done

- Every acceptance criterion in the ten specs passes, including the six **Doc 10 §18 business rules** as integration tests (one project, one version, no edit after submit without return, evidence on failed items, actions linked to the inspection, history unchanged after a template edit).
- **Version tests**: publish v2 while an inspection on v1 is open → it stays on v1, its page shows v1's questions; results compared by item key across versions.
- **Workflow tests**: every allowed and refused transition of `INSPECTION_WORKFLOW` with the right permission, self-approval refused, two reviewers racing → one wins, the other gets `INSPECTION_TRANSITION_NOT_ALLOWED`.
- **Offline tests** (API integration, sync helpers from Sprint 9): start + 10 item results + 3 photos sent twice → one inspection, one number, no duplicate rows; an item changed online and offline → `SYNC_CONFLICT` for that item only; a different item never conflicts; a superseded version within the window accepted, outside refused (`TEMPLATE_VERSION_NOT_ALLOWED`); a reassigned inspection's offline changes refused (`INSPECTION_NOT_INSPECTOR`).
- **Web unit tests**: `scoreInspection` (every method, N/A and Not inspected left out, critical items), template schema validation, the outbox label rendered in both languages.
- **Findings and actions**: approve creates exactly the "Raise action" actions in the same batch (a failure leaves no action, no number); closing the last action closes the inspection; voiding an action re-opens its finding.
- Matrix test extended with the five permissions; read-only route review (PLT-11) lists every new write.
- Browser check in **Arabic and English at 375 px**, demo company, on the **production build** for the offline part: Company Administrator creates and publishes a template (two sections, five items, percentage with pass mark) → Safety Officer plans an inspection for an Inspector → the Inspector, **offline**, starts it, records results with a Fail with two photos, sees the live score → back online: it syncs, gets its number → submits → HSE Manager reviews, returns it with a reason → Inspector fixes and submits → reviewer approves with one action raised → the action owner closes the action (verified) → the inspection shows **Closed**. Template edited to v2 afterwards: the closed inspection still shows v1.
- `npm run check` and `npm run build` pass; migrations apply to a fresh local D1 and on top of the Sprint 9 data.
- `03_DATABASE.md`, `04_API.md`, the module README (`modules/inspection/README.md`) and `modules/offline/README.md` (the first real consumer) are updated.
