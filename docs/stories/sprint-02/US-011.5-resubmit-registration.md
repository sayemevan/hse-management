# US-011.5 — Resubmit a Rejected Registration

| Field    | Value                        |
| -------- | ---------------------------- |
| Epic     | Epic 02 — Company Management |
| Priority | Must                         |
| Status   | Approved                     |
| Sources  | D-31; O-12, O-15; T-10       |

## Business Goal

Let a rejected applicant fix what the System Owner asked for and send the same application back, without starting over (D-31).

## Description

The link in the rejection email opens the application pre-filled, with the System Owner's reason shown at the top. The applicant edits it and resubmits, and it returns to the review queue.

## Actors

Applicant.

## Preconditions

A `rejected` application with an unexpired resubmission token.

## User Flow

1. Open the link from the rejection email (`<base>/register/resubmit?token=…`).
2. See the reason from the System Owner, and the form pre-filled with the application.
3. Change what's needed. The password field is empty; leaving it empty keeps the original password.
4. Select **Resubmit application**.
5. See "Your application has been sent for review again."

## Functional Requirements

The system shall:

1. Load the application through the token (`GET`, read-only). The response never contains the password hash.
2. Allow editing every field from US-011.1 except the applicant email. Changing the email means a new application, because the email was verified.
3. Re-validate everything on the server, including subdomain availability. The application's own reserved subdomain counts as available to it.
4. In one batch: consume the token, update the application, set it back to `submitted` with a new `submitted_at`, enqueue `registration.submitted` and `registration.new_for_review`, and audit.
5. Keep earlier decisions in `registration_review`, so the System Owner sees the full history.

## Validation Rules

As US-011.1. The password is optional here; if it is given, it must meet D-03 and match its confirmation. The bot check (Turnstile) applies.

## Permission Rules

Anyone with a valid resubmission link. Base domain only.

## Database Impact

Updates `company_registration` and `one_time_token`; inserts `email_outbox` and `audit_log` rows.

## API Requirements

- `GET /api/v1/registrations/resubmission?token=…` → the application fields and the latest rejection reason
- `PUT /api/v1/registrations/resubmission` with `{ token, ...fields, password?, turnstileToken }` → `{ status: 'submitted' }`

## UI Requirements

- The same form as US-011.1, with a warning-style notice at the top: "Changes requested: {reason}".
- The email is shown read-only, with a note on why.
- The password section is collapsed under "Change password (optional)".

## Error Handling

| Situation                     | Message                                                                       |
| ----------------------------- | ----------------------------------------------------------------------------- |
| Link invalid, used or expired | "This link has expired. If you still want to join, start a new registration." |
| Subdomain now unavailable     | Same message as US-011.1                                                      |

## Notifications

`registration.submitted` (applicant) and `registration.new_for_review` (System Owners).

## Audit Requirements

`registration.resubmitted` (actor null; changed field names only, never values such as the password).

## Acceptance Criteria

- The resubmission link shows the reason and the pre-filled application.
- After resubmission the application is back in the queue with its full history.
- A used or expired link can't be reused.
- The original password still works after approval if it wasn't changed.

## Test Scenarios

- **Positive:** fix the phone number and resubmit; change the plan; change the password; approve afterwards and sign in.
- **Negative:** reuse the token; expired token (30 days + 1 minute); try to change the email; a subdomain taken by another company.

## Future Improvements

Showing the applicant which fields the System Owner flagged.
